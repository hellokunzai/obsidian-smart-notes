## Vault Mind 插件 skill 搜不到 bug 修复（v0.9.1）

- **根因**：skill 扫描目录 = `<aiFolderName>/skills`（`aiFolderName` 即设置项「数据存储路径」，默认 `.vaultmind`）。用户把它改成了 `.workbuddy`，插件转去读 `<vault>/.workbuddy/skills`，但 skill `.md` 还留在旧目录（如 `.vaultmind/skills`），改名不会自动迁移 → 列表为空。
- **修复 1（自动迁移）**：`src/utils/aiFolder.ts` 新增 `migrateAiFolder(oldName,newName)`，把旧目录下的 `skills/`、`memory/`、`sessions/` 搬到新目录（不覆盖同名文件，搬完清理空旧目录）；在 `src/main.ts` 的 `saveSettings()` 检测到 `aiFolderName` 变更时调用，并加 Notice 提示。
- **修复 2（路径显示）**：`src/settings.ts` 在 Skill 分组里显示当前解析出的扫描目录（`getSkillsDir()`），新增 i18n 键 `settings.defaultSkills.pathHint`（zh/en），并把 `settings.aiFolderName.desc` 改为提示「修改会自动迁移」。
- **版本**：manifest/package/versions 升到 `0.9.1`。`npm run build` 通过（tsc 类型检查 + esbuild），安全扫描无 `createContextualFragment/new Function/eval`。
- **给用户的解法**：设置页现在会显示「当前 skill 扫描目录：<path>」。若 skill 在旧目录，最简单触发迁移：把「数据存储路径」临时改回旧名保存，再改回 `.workbuddy` 保存即可自动搬。

## 真凶：`.workbuddy` 隐藏文件夹不被 Obsidian 索引（扫不到 skill 的终极原因）
- 用户 vault 实际路径 `D:\WorkSprace\obsidian\obsidian_vault`（插件装在其 `.obsidian/plugins/vault-mind`，data.json 的 aiFolderName=.workbuddy）。
- 磁盘上 `.workbuddy/skills/{obsidian-plugin-dev,wechat-article-studio}/SKILL.md` 等 `.md` 真实存在，已装 main.js 也同步了本次改动，路径正确——但 `collectSkillFiles` 仍返回空。
- **根因**：Obsidian vault API 不索引 `.` 开头的隐藏文件夹，`vault.getAbstractFileByPath(".workbuddy/skills")` 返回 `undefined` → 空列表。插件自建文件（README/memory/sessions）会被索引，外部复制的 skill 不会。
- **修复方向**：「数据存储路径」改用非隐藏名（如 `vaultmind`）；或改 `collectSkillFiles` 走 `vault.adapter` 直接读文件系统绕开隐藏文件夹缓存。待用户确认选哪种。

## 最终修复（v0.9.2）：改用 vault.adapter 扫描 skill
- 用户选择保留 `.workbuddy` 命名，改代码支持隐藏目录。
- `src/skills/skills.ts` 的 `collectSkillFiles` 改为 async，用 `vault.adapter.list()` + `vault.adapter.stat()` 递归收集 `.md`（返回相对 vault 根的路径数组）；`listSkills`/`buildSkillContext` 改用 `vault.adapter.read()` 读内容，彻底绕开 vault 缓存对隐藏文件夹的索引限制。
- `ListedFiles = { files: string[]; folders: string[] }`，`stat` 返回 `Stat | null`，已按类型修正；移除未用的 `TFile/TFolder` import，加 `Stat`。
- 版本 0.9.2，构建通过，安全扫描无红线；bundle 内含 `adapter.list/stat/read`。重载插件后 `.workbuddy/skills` 下的 `SKILL.md`（如 obsidian-plugin-dev、wechat-article-studio）即可被识别。
- 注意：`obsidian-skills/skills/{json-canvas,bases,markdown}` 这几层目前只有空文件夹，无 `.md`，所以不会单独显示为 skill；需要确保套件内有实际 `.md` 文件。

## v0.9.3：skill 套件化扫描（只加载 SKILL.md）
- 用户期望：`.workbuddy/skills` 下应显示 5 个 skill —— `obsidian-plugin-dev`、`wechat-article-studio`、`obsidian-skills/json-canvas`、`obsidian-skills/obsidian-bases`、`obsidian-skills/obsidian-markdown`（后三个是套件包里的子套件）。
- 之前逻辑把每个 `.md` 都当 skill，导致显示过多且把参考资料也列出来；现改为**套件模型**：一个 skill = 一个文件夹 + 该文件夹下的 `SKILL.md`。
- `src/skills/skills.ts` 重写 `collectSkillFiles`：
  - 只收集名为 `SKILL.md` 的文件；
  - 遍历 `skills/` 下每个文件夹，若其根目录有 `SKILL.md`，则作为一个 skill，不再深入递归；
  - 若文件夹下没有 `SKILL.md`，则递归进入其子文件夹继续寻找（支持套件包里嵌套多个子套件）。
- `listSkills` 的 fallback 名：当文件是 `SKILL.md` 时，用所在文件夹名作为默认展示名（如 `obsidian-plugin-dev`、`obsidian-skills/json-canvas`），否则用相对路径。
- 版本 0.9.3，构建通过，安全扫描无红线。
